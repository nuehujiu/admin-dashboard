# API 自动化测试

本目录提供两套等价的自动化测试，覆盖 20 个接口（认证 / 用户 / 角色 / 看板）的正向、异常与鉴权用例。

> 2026-11-10 后端新增商品（7 个）与系统设置（3 个）共 10 个接口，**这两组用例尚未补进本目录**，现有 66 条用例不受影响。商品/设置的验证目前靠 `研发流程/06` 的 curl 清单与 Mock 对照，补用例时按同一套断言风格加 `TC-GOODS-*` / `TC-SET-*`。

## 方式一：Node 脚本（CI / 本地快速回归）

```bash
# 需先启动后端 (npm run dev 或 npm start)
node tests/api.test.mjs

# 指定其他环境
API_BASE=http://localhost:3001 node tests/api.test.mjs
```

- 共 66 个用例，逐条输出 ✓/✗，失败会给出「期望值 vs 实际值」
- 结束后生成 JSON 报告 `tests/report.json`（含每条用例耗时），适合 CI 归档
- 存在失败时进程退出码为 1，可直接接入流水线
- 测试使用 `t_api_` 前缀的临时用户/角色，结束前自动清理，不影响演示数据

## 方式二：Apifox 自动化测试

1. 打开 Apifox → 新建或选择项目 → **项目设置 → 导入数据 → Postman**
2. 选择本目录的 `postman_collection.json`，勾选「导入接口用例」，确认导入
3. 进入 **自动化测试 → 新建测试场景**，按文件夹顺序把导入的接口用例拖入
   （顺序：健康检查 → 认证 → 用户管理 → 角色管理 → 数据看板 → 通用错误）
4. 点击「运行」，即可看到每条用例的断言结果与报告

### 集合内置的关键机制

| 机制 | 说明 |
| --- | --- |
| 环境变量 | 集合变量 `baseUrl` 默认 `http://localhost:3000`，换环境改这一处即可 |
| token 自动提取 | 「登录 admin」请求的后置脚本会把 `token`、`adminId`、`adminRoleId` 写入集合变量，后续请求自动携带 `Bearer {{token}}` |
| 动态测试数据 | 注册 / 新增用户 / 新增角色的用户名、编码用 `Date.now()` 动态生成，可反复运行不冲突 |
| 断言 | 每个请求都有 `pm.test` 断言（业务码、关键字段、异常分支提示语），与 Node 脚本用例一致 |
| 数据清理 | 临时用户与临时角色在用例末尾删除，跑完不残留脏数据 |

> 导入后如果想把负向用例（401 / 404 / 非法参数）单独编排，也可以在 Apifox 的测试场景里自由增删，断言脚本已随用例一并导入。

## 测试覆盖清单

- **健康检查**：`GET /api/health`
- **认证**：注册成功 / 重复注册 / 参数不足 / 用户名或密码过短；登录成功 / 密码错误 / 账号禁用 / 用户不存在；`/me` 有效 token / 无 token 401 / 无效 token 401
- **用户管理**：分页与 keyword / status 筛选；新增 / 重名 / 缺必填；详情 / 404；编辑昵称邮箱密码并验证登录；禁用→登录被拒→恢复→可登录；不能禁用或删除自己；status 非法值；删除后详情 404、登录失败
- **角色管理**：列表含内置角色；新增 / 重复 code / 缺必填；编辑生效；菜单权限分配→读回→清空；删除有用户的角色被拒；删除空角色成功
- **数据看板**：overview 字段完整非负；trend 默认 30 天、日期连续、`days=0` 回退默认、负数钳制为 1、超限钳制为 90；category-ratio 结构；rank 默认 TOP5、降序、`top` 钳制与非法值回退
- **通用**：未登录统一 401、不存在接口 404、非法 JSON 400

## 已知的边界行为（非 Bug，测试已按实际契约断言）

- `GET /api/dashboard/trend?days=0` 返回默认 30 天（代码中 `0 || 30`，把 0 视为未传），而非钳制为 1 天；负数才会被钳制为 1
- `GET /api/roles/:id/menus` 对不存在的角色返回 `code=0, []` 而非 404，与其他接口的 404 语义不一致，建议统一（如需修改，改 `roleController.getMenus`）
