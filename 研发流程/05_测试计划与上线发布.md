## 5. 接口自动化（Apifox）

**场景**：`test1`，35 步，6 分组（0-健康检查 1 / 1-认证 6 / 2-用户管理 13 / 3-角色管理 8 / 4-数据看板 6 / 5-通用错误 1）。
搭建步骤与逐字脚本见 [`apifox-测试场景搭建步骤.md`](./apifox-测试场景搭建步骤.md)、[`apifox-脚本.md`](./apifox-脚本.md)、[`apifox-自动化测试.md`](./apifox-自动化测试.md)。

### 5.1 断言原则（必读）

- **不能只依赖"HTTP 200"**：业务失败也是 200，必须断言 `$.code`；
- 每条成功用例断言 `code=0` + 关键业务字段；每条失败用例断言 `code=1` + `message` 包含关键字；
- 命名断言用服务端返回值，不要用客户端变量（见 5.3）。

### 5.2 负向用例（7 条，必须存在）

| # | 用例 | 期望 |
| --- | --- | --- |
| 1 | 未登录访问 `/api/auth/me` | HTTP 401 + `code=401` + `未登录或 token 缺失` |
| 2 | 访问不存在接口 | HTTP 404 + `code=404` + `接口不存在:` |
| 3 | 重复注册 | `code=1` + `用户名已被占用` |
| 4 | 禁用当前账号 | `code=1` + `不能禁用当前登录账号` |
| 5 | `status=2` | `code=1` + `status 只能为 0 或 1` |
| 6 | 删除仍有用户的角色 | `code=1` + `该角色下仍有用户，无法删除` |
| 7 | 请求体不是合法 JSON | **HTTP 400** + `code=400`，message 为解析器英文原文（如 `Expected double-quoted property name in JSON at position 21`） |

> 负向用例返回 401/404 是**正确行为**，要在该步骤「后置操作」里把「校验响应（契约测试）」**关闭**，
> 否则 Apifox 会拿 401/404 去比对接口文档里声明的 200，永远红。

### 5.3 三个反复踩到的坑（务必按此排查）

| 症状 | 真因 | 处理 |
| --- | --- | --- |
| 断言数成对翻倍，`expected '...593' to deeply equal '...590'`（差 2–5ms） | `Date.now()` 在「接口级」和「步骤级」**各执行一次**，生成两个不同用户名 | 只在一处生成；或断言改为 `code=0` + `id` 匹配 + 字段存在，不比对动态用户名 |
| 分配权限返回「权限分配成功」但读回 `[]` | 请求 body 实际是 `{"menu_ids": []}` → 先删后插、一条不插、仍返回成功 | 检查该步骤 Body 是否为 JSON 且 `menu_ids` 有值；Header 必须 `Content-Type: application/json`（`text/plain` 会让 body 被吞） |
| 改了脚本重跑却毫无变化 | 场景绑定的是**另一模块下的同名接口副本** | 点步骤后置区的「接口 ›」看左侧被高亮的是哪个模块；或重建场景只绑一份接口 |

其他注意事项：

- 报告页是**静态快照**：改脚本后必须重新「运行」→「查看报告」→ 选最新那条，旧报告数值不会变。
- 末尾自动清理脚本（删除注册/新增产生的用户与角色）需确认生效，避免库内堆积 `apifox_*` 数据。
- 集合变量 10 个：`baseUrl`、`token`、`adminId`、`adminRoleId`、`newUserId`、`newRoleId`、`regUsername`、`regUserId`、`tmpUsername`、`tmpRoleCode`（`regUserId` 由注册步骤后置脚本写入，只服务末尾自动清理）。

### 8.2 部署步骤

**后端（Express）**

```bash
cd backend
npm ci --omit=dev          # 只装生产依赖
cp .env.example .env       # 按生产填写
node app.js                # 或 pm2 start app.js --name admin-dashboard-api
```

**前端（Vite）**

```bash
cd frontend
npm ci
npm run build              # 产出 dist/
```

**Nginx（同域反代，避免跨域）**

```nginx
server {
    listen 80;
    server_name admin.example.com;
    root /var/www/admin-dashboard/dist;

    location / {
        try_files $uri $uri/ /index.html;   # 单页路由必须回退 index.html
    }

    location /api/ {
        proxy_pass         http://127.0.0.1:3000/api/;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}
```

**要点**

- 前端与后端**同域**（`/api` 反代），生产环境不需要再开 CORS；
- `proxy_pass` 末尾的 `/api/` 与 `location` 保持一致，否则路径会被截断；
- **不要**把反代指到 3001（那是 Mock 端口）。

### 8.4 回滚方案

| 场景 | 动作 | 目标 |
| --- | --- | --- |
| 前端异常 | 切回上一版 `dist`（保留最近 2 个版本目录） | 1 分钟内恢复 |
| 后端异常 | `pm2 rollback admin-dashboard-api` 或切换上一份代码 | 2 分钟内恢复 |
| DB 变更异常 | 用变更前备份还原（`mysqldump` 备份每次发布前执行） | 按备份时间 |

**发布前必备份**：`mysqldump -u root -p admin_dashboard > backup_$(date +%F_%H%M).sql`
