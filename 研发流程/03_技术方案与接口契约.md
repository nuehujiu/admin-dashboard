## 1. 系统架构

```
┌────────────────────────────┐   HTTP / JSON            ┌────────────────────────────┐
│  React 前端  :5173         │ ───────────────────────▶ │  Express 后端  :3000       │
│  Vite dev / build(dist)    │ ◀─────────────────────── │  路由前缀 /api             │
└────────────────────────────┘  Authorization: Bearer   └──────────┬─────────────────┘
                                                                    │ mysql2 连接池（10）
                                                          ┌─────────▼──────────────┐
                                                          │ MySQL 8.0              │
                                                          │ admin_dashboard        │
                                                          └────────────────────────┘

可选：前端不接真库时 → 访问 :3001 的 Mock 服务（契约同构，见 06 文档）
```

**请求链路**

1. 前端 axios 实例 `baseURL: '/api'` → Vite `server.proxy` 转发到 `http://localhost:3000`
2. `app.js` 依次挂载：CORS → `express.json()` → `express.urlencoded()` → `/api/health` → 四组业务路由 → 404 → 统一错误处理
3. 业务路由用 `authRequired` 校验 JWT，payload 挂到 `req.user`
4. 控制器用 `config/db.js` 的 `query()` 执行参数化 SQL，`utils/response.js` 统一包装响应
5. MySQL 连接池 `connectionLimit:10`、`dateStrings:true`（日期直接返回字符串）

## 5. 统一响应与错误码

**所有接口返回 JSON**

```json
{ "code": 0, "message": "ok", "data": null }
```

| code | 含义 | HTTP |
| --- | --- | --- |
| 0 | 成功 | 200 |
| 1 | 业务错误（参数不合法、用户名已占用、角色下有用户、status 非法…） | **200** |
| 400 | 请求体 JSON 语法错误（`express.json()` 抛 SyntaxError） | 400 |
| 401 | 未登录 / token 无效或过期 | 401 |
| 404 | 用户/角色不存在、接口不存在 | 404 |
| 500 | 服务器异常 | 500 |

> ⚠️ **业务错误是 HTTP 200 + code 1**。前端判断成败**只能看 `code`**，不能只看 HTTP status；`err.response.status === 200` 不代表成功。
>
> ⚠️ **400 是唯一的"语法事故"**：body 不是合法 JSON 时（最常见于 `"username": {{变量}}` 变量为空、`role_id` 加了引号撑坏 JSON），
> 后端返回 `HTTP 400 + {"code":400,"message":"Expected double-quoted property name in JSON at position 21 ..."}`，
> `message` 是解析器的**英文原文**。前端不要直接展示，统一提示「请求参数格式错误」，同时去查是哪个变量为空。

分页成功响应固定为：

```json
{ "code":0,"message":"ok","data":{ "list":[], "total":0, "page":1, "pageSize":10 } }
```

`data` 直接就是列表（裸数组/数组）的接口，不是分页对象：`GET /api/roles`、`GET /api/roles/:id/menus`（数字数组）、`GET /api/dashboard/{trend,category-ratio,rank}`（数组）。

## 6. 鉴权约定

**token 获取**：`POST /api/auth/login` → `data.token`

**携带方式**：

```
Authorization: Bearer <token>
```

（`Bearer` 后有**一个空格**；缺失或格式错都会被判 401。）

**JWT payload**（前端可从 `me` 拿到等价信息，不必解析 token）：

```json
{ "id": 1, "username": "admin", "role_id": 1, "role_name": "超级管理员", "iat": 1794232449, "exp": 1794239649 }
```

**401 文案**

| 场景 | message |
| --- | --- |
| 没带 token / 空 token | `未登录或 token 缺失` |
| token 被改、过期、密钥变更 | `token 无效或已过期` |

**无需鉴权**：`GET /api/health`、`POST /api/auth/register`、`POST /api/auth/login`。

**前端处理**：请求拦截器注入 header；响应拦截器见 401 → 清 store → `window.location.replace('/login')`。

> 后端 `authRequired` **只验登录，不验权限**。operator 的 token 也能调 `/api/users`，接口级 RBAC 属已知缺口（见开发文档 14.1）。

## 7. 接口契约（完整，30 个）

### 7.1 健康检查

```
GET /api/health
→ { "code":0,"message":"ok","data":{ "time":"2026-11-09T06:26:00.000Z" } }
```

用于前端探活、Vite 启动自检、上线冒烟。

### 7.2 认证 `/api/auth`

| 方法 | 路径 | 鉴权 | 入参 | 出参 `data` |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/register` | 否 | `{username, password, nickname?, email?}` | `{id}` |
| POST | `/api/auth/login` | 否 | `{username, password}` | `{token, user}` |
| GET | `/api/auth/me` | 是 | — | 用户信息 + `menus` + `permissions` |

**register 校验顺序与文案**

1. 缺 `username` 或 `password` → `用户名和密码不能为空`
2. `username.length < 3` 或 `password.length < 6` → `用户名至少 3 位，密码至少 6 位`
3. 用户名重复 → `用户名已被占用`
4. 成功 → `注册成功`，`data: { id }`

默认分配 `code='operator'` 的角色（role_id=2）。

**login 校验顺序与文案**

1. 缺参 → `用户名和密码不能为空`
2. 用户不存在 → `用户名或密码错误`
3. `status === 0` → `账号已被禁用，请联系管理员`
4. bcrypt 比对失败 → `用户名或密码错误`
5. 成功 → `登录成功`

`user` 结构（**不含 password / status**）：

```json
{ "id":1,"username":"admin","nickname":"管理员","email":"admin@example.com",
  "avatar":null,"role_id":1,"role_name":"超级管理员" }
```

**me 返回**：

```json
{
  "id": 1, "username": "admin", "nickname": "管理员", "email": "admin@example.com",
  "avatar": null, "role_id": 1, "status": 1, "role_name": "超级管理员",
  "menus": [
    { "id":1,"parent_id":0,"name":"数据看板","path":"/dashboard","icon":"dashboard",
      "type":1,"permission":"dashboard:view","sort":1 }
  ],
  "permissions": ["dashboard:view","sales:view","user:list","..."]
}
```

要点（前端必须知道）：

- `menus` **只含 `type=1`**（菜单），`ORDER BY sort` —— 注意这是**全表按 sort 排**，父子会混排（`用户管理 sort=1` 会排在 `系统管理 sort=3` 前面），仍是**扁平数组**，所以前端必须按 `parent_id` 建树，**不能假设"父项一定在子项之前"**。
- `permissions` 是**全部菜单+按钮**的 permission（`null` 已过滤），**未去重、未排序**，只能用 `includes()`。
- 侧栏渲染用 `menus`，按钮显隐用 `permissions`。

### 7.3 用户管理 `/api/users`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/users` | 分页列表 |
| GET | `/api/users/:id` | 详情 |
| POST | `/api/users` | 新增 |
| PUT | `/api/users/:id` | 编辑 |
| PUT | `/api/users/:id/status` | 启停 |
| DELETE | `/api/users/:id` | 删除 |

**列表 query**

| 参数 | 默认 | 规则 |
| --- | --- | --- |
| `page` | 1 | 小于 1 归 1 |
| `pageSize` | 10 | 1–100，超出被 clamp |
| `keyword` | — | 模糊匹配 **username 或 nickname**（**不含 email**） |
| `role_id` | — | 精确 |
| `status` | — | `1`/`0`，空串视为不过滤 |

排序固定 `ORDER BY u.id DESC`（新用户在前）。列表项字段：

```json
{ "id":1,"username":"admin","nickname":"管理员","email":"admin@example.com","avatar":null,
  "role_id":1,"role_name":"超级管理员","status":1,"created_at":"2026-11-09 14:12:03" }
```

详情比列表多一个 `updated_at`。

**新增**：`username`、`password`、`role_id` 必填 → 缺一 `用户名、密码、角色为必填项`；用户名重复 → `用户名已被占用`；成功 `新增成功`，`data:{id}`。

**编辑**：可选 `nickname`、`email`、`role_id`、`password`；传 `role_id` 会校验存在性（`角色不存在`）；传 `password` 才重算 bcrypt；只更新传入字段。

**启停**：body `{"status": 0|1}`；非 0/1 → `status 只能为 0 或 1`；操作自己 → `不能禁用当前登录账号`；成功 `操作成功`。

**删除**：操作自己 → `不能删除当前登录账号`；不存在 → 404 `用户不存在`；成功 `删除成功`。

### 7.4 角色管理 `/api/roles`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/roles` | 列表（裸数组，每项带 `user_count`） |
| POST | `/api/roles` | 新增 `{name*, code*, description?}` |
| PUT | `/api/roles/:id` | 编辑 `{name, description}` |
| DELETE | `/api/roles/:id` | 删除 |
| GET | `/api/roles/:id/menus` | 已分配 `menu_id` 数组 |
| PUT | `/api/roles/:id/menus` | 全量覆盖 `{ "menu_ids":[1,4,6] }` |

**列表响应**（注意是数组，不是 `{list,total}`）：

```json
{ "code":0,"message":"ok","data":[
  { "id":1,"name":"超级管理员","code":"admin","description":"拥有全部权限",
    "created_at":"2026-11-09 10:00:00","user_count":1 }
] }
```

**新增**：`name`/`code` 必填 → `角色名称和编码为必填项`；code 重复 → `角色编码已存在`；成功 `新增成功`。

**编辑**：不存在 → 404 `角色不存在`；**代码不校验 name**，只传 `description` 会把 name 写成 `undefined` 导致数据库报错 → **前端永远传全量 `name + description`**。

**删除**：不存在 → 404；角色下仍有用户 → `该角色下仍有用户，无法删除`；成功 `删除成功`。

**读回菜单**：`GET /api/roles/:id/menus` → `data: [1,4,6]`。
⚠️ **不校验角色是否存在**：角色不存在/已被删，返回 `200 + []`，不是 404。

**分配菜单**：`PUT /api/roles/:id/menus`，body `{"menu_ids":[1,4,6]}`。
- 实现是**先 `DELETE` 该角色全部授权，再 `INSERT`**，属全量覆盖；
- `menu_ids` 为空数组时「删光不插」仍返回 `权限分配成功`（**静默假成功**）；
- body 未被解析（如 `Content-Type: text/plain`）时 `menu_ids` 默认 `[]`，结果同上；
- 只传父节点不带子节点会导致子节点权限丢失 → 勾父节点时自动带上子节点。

### 7.5 数据看板 `/api/dashboard`

**overview**

```json
{ "today_amount":18432.5,"today_amount_change":12.5,"today_qty":213,
  "total_amount":1286940.22,"total_qty":28471,"user_count":2,"record_count":150 }
```

- 所有金额/数量都是 **Number**（`DECIMAL` 已 `Number()` 转换）；
- `today_amount_change` = (今日−昨日)/昨日×100，**昨日为 0 直接返回 0**（不是 100）；
- 日期用 `toISOString()` 即 **UTC**，北京时间 00:00–08:00 会把「今日」算成前一天（已知问题）。

**trend** `GET /api/dashboard/trend?days=30`

- `days` clamp 1–90，默认 30；
- 返回**连续日期**，无销售的日期补 `{amount:0,qty:0}`，前端不用自己补点；
- 结构：`[{ "date":"2026-10-11","amount":5120.5,"qty":78 }]`

**category-ratio** → `[{ "name":"电子产品","value":1386200 }]`（`value` 为 Number，按金额降序）

**rank** `GET /api/dashboard/rank?top=5`

- `top` clamp 1–20，默认 5；
- → `[{ "id":1,"name":"电子产品","amount":1386200,"qty":2841 }]`

### 7.6 商品管理 `/api/goods`（2026-11-10 新增）

**list** `GET /api/goods?page&pageSize&keyword&category&status`

- `keyword` 模糊匹配 **`name` 或 `sku`**；`category` 精确匹配分类名；`status` 精确 0/1；空串视为不过滤；
- `ORDER BY id DESC`；分页同 §8（默认 10，上限 100）；
- 返回 `{list,total,page,pageSize}`，`list` 元素见下。

```json
{ "id":1,"name":"无线蓝牙耳机 Pro","sku":"SKU-EAR-001","category":"电子产品",
  "price":"899.00","stock":120,"sales":320,"status":1,"image":null,
  "description":"…","created_at":"2026-11-10 10:45:16","updated_at":"…" }
```

> ⚠️ **`price` 是字符串 `"899.00"`**（MySQL `DECIMAL` 经 mysql2 返回字符串），不是 Number。列表排序/合计前必须 `Number(g.price)`，直接 `+` 会变字符串拼接。

**categories** `GET /api/goods/categories`

- 返回**裸字符串数组**（`["家居生活","服饰鞋包","电子产品","美妆个护","食品生鲜"]`），直接喂 Select；
- 路由里必须排在 `/:id` 之前，否则 `categories` 会被当成 id。

**detail / create / update / delete / status**

| 方法 | 路径 | 要点 |
| --- | --- | --- |
| GET | `/api/goods/:id` | 不存在 → `404 商品不存在` |
| POST | `/api/goods` | `name`+`sku` 必填 → `商品名称和 SKU 为必填项`；`price` 缺失或非数字/负数 → `价格必须为不小于 0 的数字`；`status` 非 0/1 → `status 只能为 0 或 1`；SKU 重复 → `SKU 已存在`；成功返回 `{id}` |
| PUT | `/api/goods/:id` | 只更新传入字段；空 body → `没有可更新的字段`；`sku` 改重 → `SKU 已存在`；`price/stock/sales` 负数各自报错 |
| PUT | `/api/goods/:id/status` | body `{"status":0\|1}`，message 为 `已下架` / `已上架` |
| DELETE | `/api/goods/:id` | 成功 `删除成功`；不存在 404（HTTP 200 的业务错误不存在，这里用真 404） |

- `stock=0` 不会自动下架，**库存与状态是两件事**，前端要分别处理「售罄」与「已下架」两种展示；
- `image` 目前恒为 `null`（无上传能力），前端用占位块，不要写成空 `<img>`。

### 7.7 系统设置 `/api/settings`（2026-11-10 新增）

键值表 `settings(key,value)` 存储，接口层合并默认值后返回**一个扁平对象**（不是 `[{key,value}]`）：

```json
{ "systemName":"电商后台管理系统","slogan":"用数据驱动每一次增长",
  "notice":"","themeColor":"#F5611D","siderCollapsed":0 }
```

| 方法 | 路径 | 要点 |
| --- | --- | --- |
| GET | `/api/settings` | 未设置过的字段返回默认值；`siderCollapsed` 为 **Number** 0/1 |
| PUT | `/api/settings` | 支持**部分字段**；返回保存后的完整对象；空对象 → `没有可保存的设置项`；未知 key → `不支持的设置项: xxx` |
| POST | `/api/settings/reset` | 清空表并回到默认值，返回默认对象 |

字段校验（都是 HTTP 200 + `code=1`）：

| 字段 | 规则 | 报错文案 |
| --- | --- | --- |

| `notice` | ≤200 字 | `公告不能超过 200 个字` |

## 8. 参数与分页约定

| 约定 | 规则 |
| --- | --- |
| 分页参数名 | `page` / `pageSize`（不是 `current` / `size`） |
| `page` | 从 1 开始，`<1` 归 1 |
| `pageSize` | 默认 10，范围 1–100，超出 clamp |
| 空字符串 query | 视为不过滤（`status=''` 等于不传） |
| 模糊 vs 精确 | 模糊统一叫 `keyword`；精确筛选各自具名（`role_id` / `status`） |
| 状态值 | `status` 数字 `1`/`0`（不是布尔 `enabled`） |
| 分页越界 | 返回空 `list` + 正确 `total`，前端按 `total` 重置 `page` |
| 金额格式 | 看板接口（overview/trend/ratio/rank）返回 **Number**；商品 `price` 是 **字符串 `"899.00"`**（DECIMAL 原样）。展示层统一千分位 + 两位小数 |

## 9. RBAC 数据链路

```
roles  ←─ users.role_id（外键 fk_user_role）
roles  ←─ role_menu ─→ menus（role_menu 双外键，ON DELETE CASCADE）
```

- `menus.type=1` 菜单（渲染侧栏），`type=2` 按钮（控制按钮显隐）。
- 内置角色：`admin`（超级管理员，13 条全量）、`operator`（运营，仅 `dashboard:view`、`sales:view`）。
- 菜单清单与权限标识见开发文档 6 章（13 条：1–5 菜单、6–11 按钮、12 商品管理、13 系统设置）。
- 前端权限链路：`login` 拿 token → `me` 拿 `menus`/`permissions` → Zustand 持久化 → 路由守卫过滤 + `<Auth permission="...">` 控制按钮。
- 商品/设置两个新菜单**只做可见性**，没有接口级权限中间件（与用户/角色一致，接口鉴权只校验登录）。

## 10. 数据库设计

库名 `admin_dashboard`，`utf8mb4` / `utf8mb4_unicode_ci`。`npm run init-db` 会 `DROP` 全量重建，**有数据时禁止执行**；
已有库要补商品/设置，跑增量脚本 `node sql/migrate-goods-settings.js`（不 DROP，可重复执行）。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `roles` | id, name, code(UNIQUE), description, created_at, updated_at | 角色 |
| `users` | id, username(UNIQUE), password(bcrypt), nickname, email, avatar, role_id, status, created_at, updated_at | 后台账号，**无 phone 字段** |
| `menus` | id, parent_id, name, path, icon, type, permission, sort | 菜单/按钮 |
| `role_menu` | role_id + menu_id 联合主键 | 授权关系，级联删除 |
| `categories` | id, name, sort | 销售分类（5 条种子） |
| `sales` | id, category_id, amount DECIMAL(12,2), qty, sale_date DATE | 近 30 天 × 5 分类种子 |
| `goods` | id, name, sku(UNIQUE), category, price DECIMAL(10,2), stock, sales, status, image, description, created_at, updated_at | 商品，12 条演示数据（最后一条 `stock=0`+`status=0`） |
| `settings` | key(主键), value TEXT, updated_at | 键值表，5 个键：systemName/slogan/notice/themeColor/siderCollapsed |

索引：`users.uk_username`、`users.idx_role`、`sales.idx_date`、`sales.idx_category`、`goods.uk_sku`、`goods.idx_category`、`goods.idx_status`。

> **迁移后基线**：`goods=12`、`settings=5`、`menus=13`、`role_menu=15`（admin 13 + operator 2）、`users=2`、`roles=2`、`categories=5`、`sales=150`。未跑迁移时仍为 `menus=11 / role_menu=13`。

## 11. 前端对接要点（最小可用实现）

```js
// vite.config.js
export default defineConfig({
  plugins: [react()],
  server: { port: 5173, proxy: { '/api': { target: 'http://localhost:3000', changeOrigin: true } } },
})
```

```js
// src/api/request.js —— 成功直接返回 data，失败统一提示
request.interceptors.response.use(
  (res) => {
    const { code, message: msg, data } = res.data
    if (code === 0) return data
    message.error(msg || '请求失败')
    return Promise.reject(new Error(msg))
  },
  (err) => { /* 401 → 清 store + 跳 /login；其余弹 message */ }
)
```

**必须按真实形状写的地方**

| 接口 | 前端写法 |
| --- | --- |
| `GET /api/roles` | 直接拿数组 `data.map(...)`，不要 `.data.list` |
| `GET /api/auth/me` | `menus` 扁平 → `buildMenuTree(menus)`；`permissions` 只 `includes()` |
| `GET /api/users` | `data.list` / `data.total` / `data.page` / `data.pageSize` |
| `GET /api/roles/:id/menus` | `data` 是数字数组，直接映射到 Tree 的 `checkedKeys` |
| `PUT /api/roles/:id/menus` | body 必须是 JSON；**父节点勾选要带子节点** |
| `GET /api/goods` | `data.list` 分页；`price` 先 `Number()` 再 `.toFixed(2)` |
| `GET /api/goods/categories` | `data` 是字符串数组，直接做 Select 的 options |
| `GET /api/settings` / `PUT /api/settings` | `data` 是**扁平对象**（不是数组），`siderCollapsed` 是 0/1 数字 |

`operator` 登录后 `menus` 只有 1、2 两条 —— 这是验证 RBAC 最快的一步。
